    Turning Bands at Scale Implementation Plan¶

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Make conditional turning-bands simulation compute each node's neighbours and simple-kriging weights once per batch of realizations instead of once per realization, with results bit-identical to today's per-realization path.

    Architecture: A new Conditioning (crates/simulation/src/conditioning.rs) holds, for a tile of nodes, the chosen data and their SK weights. TurningBandsEnsemble::realizations(ks, ..) walks fixed-size tiles of targets in parallel; for each tile it builds the conditioning once (per distinct domain vector of the batch) and applies it to every realization in the batch, reading residuals from a data × realization matrix (realizations contiguous). post::continuous_batched folds batches into the existing Accumulator in realization order. Every caller (summary, realization, turning_bands_to_parquet, Python TurningBands.simulate, multivariate turning-bands factors) moves to the batched path. The unconditional field gets an exact loop reorder (bands outer over a tile of points), and an optional incremental-projection variant gated on a benchmark and on a decision about bit-exactness.

    Tech Stack: Rust (rayon, nalgebra), existing estimation::krige, estimation::search::SearchTree, pyo3 bindings in crates/py.

    Global Constraints¶

    • Output identical for any thread count (AGENTS.md: "Parallelism: rayon, deterministic — identical output for any thread count. Parallel map, ordered fold.").
    • The batched path must equal today's TurningBandsEnsemble::realization bit for bit (compare with ==, which treats -0.0 == 0.0), for every realization, with domains, per-realization domains, soft boundaries, high-grade clamping, trend and nugget. Tasks 1–3 and 6 keep that; only Task 5b may relax it, and only with the user's approval.
    • Summaries must not depend on the realization batch size.
    • Compute in f64. No new dependencies. No unsafe.
    • Every feature ships in Rust and Python together; this plan changes no Python signature, so .pyi stubs and docs stay as they are.
    • PRs ≤ ~400 changed lines; branch + PR to main, never commit to main; conventional commits; no co-author trailers or AI attribution; PR bodies a few lines, no sections.
    • Never name external geostatistics libraries anywhere (code, comments, commits, PRs).
    • Never commit AGENTS.md, CLAUDE.md or this plan.
    • Run everything through mise: mise run test, mise run lint, mise run verify; single crates with mise exec -- cargo test -p simulation <filter>.

    Dependencies on other plans¶

    • Plan 1 (simulation output and writer) changes ContinuousOptions::keep from bool to a realization selection. This plan passes options through untouched and feeds the Accumulator one realization at a time, in order, so either version works. Whichever plan lands second resolves the one-line conflict in continuous_batched.
    • Plan 2 (kriging kernel) replaces the solver. Here the only solver call is krige(...) inside Conditioning::new; plan 2 swaps that single call. Sharing one neighbour search across factors is also plan 2 (Task 6 here keeps one search per factor).

    Files: - Create: crates/simulation/src/conditioning.rs - Modify: crates/simulation/src/lib.rs (add mod conditioning; after pub mod correct;) - Test: crates/simulation/src/turning_bands.rs (tests module; it has the zoned fixtures and access to the private condition)

    Interfaces: - Consumes: estimation::search::SearchTree::{neighbors_in, cap}, estimation::krige::{krige, Kind}, estimation::Sample. - Produces: - pub(crate) struct Neighbor { pub datum: u32, pub weight: f64, pub cap: Option<f64> } - pub(crate) struct Conditioning - Conditioning::new(targets: &[(f64, f64, f64)], domains: Option<&[u32]>, tree: &SearchTree, data: &[Sample], vg: &Variogram) -> Result<Conditioning> - Conditioning::of(&self, i: usize) -> &[Neighbor] - Conditioning::krige_batch(&self, i: usize, residual: impl Fn(&Neighbor, &mut [f64]), row: &mut [f64], out: &mut [f64]) -> bool

    Why the weights are reusable: krige builds its matrix and right-hand side from locations and error_variance only (crates/estimation/src/krige.rs:106-112); values enter only in the final sum. The high-grade cap (SearchTree::cap, crates/estimation/src/search.rs:807) depends on the target, the datum location and the datum's grade, never on the realization, so it changes a residual's value, not the neighbour set or the weights. The residuals condition kriges are Sample::new(loc, value), so error_variance is 0 there too.

    Why bit-exactness holds: krige computes mean + Σᵢ wᵢ·(zᵢ − mean) with mean = 0.0 (krige.rs:131). z − 0.0 == z exactly and Iterator::sum for f64 folds from -0.0 in order, so accumulating wᵢ·rᵢ in neighbour order from -0.0 and then adding 0.0 + reproduces it bit for bit.

    //! Neighbours and simple-kriging weights of nodes. They depend only on the
//! locations of the nodes and data, so they are found once and applied to
//! the residuals of every realization conditioned from the same data.

use estimation::Sample;
use estimation::krige::{Kind, krige};
use estimation::search::SearchTree;
use variogram::Variogram;

use crate::error::{Result, SimError};

/// Datum `datum` with simple-kriging weight `weight`, its grade capped at
/// `cap` by a clamping high-grade restriction.
#[derive(Debug, Clone, Copy, PartialEq)]
pub(crate) struct Neighbor {
    pub datum: u32,
    pub weight: f64,
    pub cap: Option<f64>,
}

/// The neighbours of each of a run of nodes.
pub(crate) struct Conditioning {
    offsets: Vec<usize>,
    neighbors: Vec<Neighbor>,
}

impl Conditioning {
    /// The data `tree` selects for each of `targets`, of domain `domains[i]`
    /// when given, with their weights in the simple kriging of `vg`; `data`
    /// are the samples the tree was built from.
    pub(crate) fn new(
        targets: &[(f64, f64, f64)],
        domains: Option<&[u32]>,
        tree: &SearchTree,
        data: &[Sample],
        vg: &Variogram,
    ) -> Result<Self> {
        let mut offsets = Vec::with_capacity(targets.len() + 1);
        offsets.push(0);
        let mut neighbors = Vec::new();
        for (i, g) in targets.iter().enumerate() {
            let chosen = tree.neighbors_in(g, domains.map(|d| d[i])).unwrap_or_default();
            if !chosen.is_empty() {
                let near: Vec<Sample> = chosen.iter().map(|&k| Sample::new(data[k].loc, 0.0)).collect();
                let weights = krige(Kind::Simple { mean: 0.0 }, g, &near, vg)
                    .map_err(|e| SimError::Estimation(e.to_string()))?
                    .weights;
                neighbors.extend(chosen.iter().zip(weights).map(|(&k, weight)| Neighbor {
                    datum: k as u32,
                    weight,
                    cap: tree.cap(g, None, k),
                }));
            }
            offsets.push(neighbors.len());
        }
        Ok(Self { offsets, neighbors })
    }

    pub(crate) fn of(&self, i: usize) -> &[Neighbor] {
        &self.neighbors[self.offsets[i]..self.offsets[i + 1]]
    }

    /// The kriged residual of node `i` in each realization of a batch, in
    /// `out`, summed in neighbour order as [`krige`] sums it;
    /// `residual(n, row)` writes neighbour `n`'s residual in each realization
    /// into `row` (as long as `out`). False, leaving `out`, when the node has
    /// no neighbours.
    pub(crate) fn krige_batch(
        &self,
        i: usize,
        residual: impl Fn(&Neighbor, &mut [f64]),
        row: &mut [f64],
        out: &mut [f64],
    ) -> bool {
        let near = self.of(i);
        if near.is_empty() {
            return false;
        }
        out.fill(-0.0);
        for n in near {
            residual(n, row);
            for (o, r) in out.iter_mut().zip(row.iter()) {
                *o += n.weight * r;
            }
        }
        for o in out.iter_mut() {
            *o += 0.0;
        }
        true
    }
}

    *o += 0.0 is *o + 0.0; IEEE addition is commutative, signed zeros included, so it equals krige's 0.0 + sum bit for bit. The test's extra 0.0 + out[0] mirrors condition's u + rk with u = 0.0.

        /// Realization `k` at `targets`, of codes `domains` and trend `trend`
    /// when the data have them, back-transformed to data values. Each
    /// realization may take its own `domains`, as simulated domains do.
    pub fn realization(
        &self,
        k: usize,
        targets: &[(f64, f64, f64)],
        domains: Option<&[u32]>,
        trend: Option<&[f64]>,
    ) -> Result<Vec<f64>> {
        Ok(self.realizations(k..k + 1, targets, |_| domains, trend)?.remove(0))
    }

    /// Realizations `ks` at `targets`, each as [`Self::realization`] with
    /// the node domains `domains(k)`. The targets are taken a tile at a
    /// time; a tile's neighbours and kriging weights are found once for
    /// every realization in `ks` that gives it the same domains.
    pub fn realizations<'d>(
        &self,
        ks: std::ops::Range<usize>,
        targets: &[(f64, f64, f64)],
        domains: impl Fn(usize) -> Option<&'d [u32]> + Sync,
        trend: Option<&[f64]>,
    ) -> Result<Vec<Vec<f64>>> {
        if ks.is_empty() || ks.end > self.bands.len() {
            return Err(SimError::InvalidParameters(format!(
                "no realizations {ks:?} among {}",
                self.bands.len()
            )));
        }
        for k in ks.clone() {
            self.transforms(targets.len(), domains(k), trend)?;
        }
        let b = ks.len();
        let mut residuals = vec![0.0; self.data.len() * b];
        for (j, row) in residuals.chunks_mut(b).enumerate() {
            for (r, k) in row.iter_mut().zip(ks.clone()) {
                *r = self.transforms.scores[j] - self.at_data[k][j];
            }
        }
        let tiles: Vec<Vec<Vec<f64>>> = targets
            .par_chunks(TILE)
            .enumerate()
            .map(|(t, tile)| {
                let start = t * TILE;
                let codes = |kk: usize| domains(ks.start + kk).map(|d| &d[start..start + tile.len()]);
                let mut groups: Vec<(Option<&[u32]>, Vec<usize>)> = vec![];
                for kk in 0..b {
                    match groups.iter_mut().find(|(c, _)| *c == codes(kk)) {
                        Some((_, members)) => members.push(kk),
                        None => groups.push((codes(kk), vec![kk])),
                    }
                }
                let mut out = vec![vec![]; b];
                for (codes, members) in groups {
                    let c = Conditioning::new(tile, codes, &self.tree, &self.data, &self.vg)?;
                    let fields: Vec<Vec<f64>> = members
                        .iter()
                        .map(|&kk| self.bands[ks.start + kk].field_serial(tile))
                        .collect();
                    let (mut row, mut rk) = (vec![0.0; members.len()], vec![0.0; members.len()]);
                    for kk in &members {
                        out[*kk] = Vec::with_capacity(tile.len());
                    }
                    for i in 0..tile.len() {
                        let domain = codes.map(|d| d[i]);
                        let residual = |n: &Neighbor, row: &mut [f64]| {
                            let d = n.datum as usize;
                            if n.cap.is_none() && self.data[d].domain == domain {
                                for (r, &kk) in row.iter_mut().zip(&members) {
                                    *r = residuals[d * b + kk];
                                }
                            } else {
                                let s = self.score(d, domain, n.cap);
                                for (r, &kk) in row.iter_mut().zip(&members) {
                                    *r = s - self.at_data[ks.start + kk][d];
                                }
                            }
                        };
                        let found = c.krige_batch(i, residual, &mut row, &mut rk);
                        let at = trend.map_or(0.0, |t| t[start + i]);
                        let transform = self.transforms.domains[domain.unwrap_or(0) as usize]
                            .as_ref()
                            .expect("checked");
                        for (m, &kk) in members.iter().enumerate() {
                            let u = fields[m][i];
                            let score = if found { u + rk[m] } else { u };
                            out[kk].push(transform.back(score, at));
                        }
                    }
                }
                Ok(out)
            })
            .collect::<Result<_>>()?;
        let mut all: Vec<Vec<f64>> = (0..b).map(|_| Vec::with_capacity(targets.len())).collect();
        for tile in tiles {
            for (a, t) in all.iter_mut().zip(tile) {
                a.extend(t);
            }
        }
        Ok(all)
    }

    Task 5b (gated): Incremental projection along straight runs¶

    Do not start without the user's go-ahead. Along a straight, equally spaced run of points (a block-model row), each band's coordinate is an arithmetic progression: t_i = t_0 + i·Δt, one multiply-add per point instead of a dot product.         return Err(SimError::InvalidParameters(
            "need at least one realization".into(),
        ));
    }
    let mut accs = (0..variables)
        .map(|_| Accumulator::new(n, options))
        .collect::<Result<Vec<_>>>()?;
    for start in (0..n).step_by(batch.max(1)) {
        let ks = start..(start + batch.max(1)).min(n);
        let done = simulate(ks.clone())?;
        if done.len() != ks.len() {
            return Err(SimError::InvalidParameters(format!(
                "{} realizations for {} indices",
                done.len(),
                ks.len()
            )));
        }
        for values in done {
            if values.len() != variables {
                return Err(SimError::InvalidParameters(format!(
                    "one realization per variable ({variables}) needed"
                )));
            }
            accs.iter_mut().zip(values).try_for_each(|(a, v)| a.add(v))?;
        }
    }
    Ok(accs.into_iter().map(Accumulator::finish).collect())
}

    /// As [`multivariate`], `batch` realizations at a time: `simulate(j, ks)`
/// returns realizations `ks` of factor `j` at the nodes.
pub fn multivariate_batched(
    n: usize,
    factors: usize,
    transform: &Decorrelation,
    options: &ContinuousOptions,
    support: Option<&BlockSupport>,
    batch: usize,
    mut simulate: impl FnMut(usize, std::ops::Range<usize>) -> Result<Vec<Vec<f64>>>,
) -> Result<Vec<ContinuousSummary>> {
    crate::post::continuous_many_batched(n, factors, options, batch, |ks| {
        let columns = (0..factors)
            .map(|j| simulate(j, ks.clone()))
            .collect::<Result<Vec<Vec<Vec<f64>>>>>()?;
        (0..ks.len())
            .map(|kk| {
                let nodes = columns.first().map_or(0, |c| c[kk].len());
                let rows: Vec<Vec<f64>> = (0..nodes)
                    .map(|i| columns.iter().map(|c| c[kk][i]).collect())
                    .collect();
                let back = transform.back(&rows);
                (0..factors)
                    .map(|v| {
                        let values: Vec<f64> = back.iter().map(|r| r[v]).collect();
                        match support {
                            Some(s) => s.mean(&values),
                            None => Ok(values),
                        }
                    })
                    .collect()
            })
            .collect()
    })
}

    Self-review notes¶

    • Coverage: chunk-major conditioning (Tasks 1–2), residuals data × realization contiguous (Task 2), per-domain and per-realization domains (Task 2 grouping), caps verified to change values not weights (Task 1 rationale + regression test with HighGradeMode::Clamp), streaming summaries and keep (Task 3, plan 1 compatible), realization batching by memory (Task 2 batch, Task 3), deterministic fixed TILE (Task 2), incremental field along rows (Tasks 5a exact / 5b gated), multivariate factors (Task 6), benchmarks (Task 4).
    • The "small GEMM" is realized as the per-node loop over neighbours with realizations innermost and contiguous (krige_batch); a reordered GEMM would break bit-exactness, which the constraints forbid.
    • Masked and sub-blocked models need no special path: tiles are index ranges over whatever targets arrive.

    Open questions¶

    1. Task 5b: may the field differ at ~1e-12 between chunkings (in-memory vs streamed rows) for an incremental projection? Default in this plan: no, keep bit-exactness.
    2. Task 6: with impute and a high-grade restriction, grades differ per realization, so the selection itself would differ. The plan rejects that combination with an error in the batched path and keeps the old path for it. Acceptable, or should it fall back silently to the per-realization path?
    3. BATCH_BYTES = 1 GiB and multivariate batch = 8 are fixed; should they follow available memory (plan 4 plans memory-driven batches for SGS) or a user argument?
    4. Bands memory: TurningBandsEnsemble::new still builds bands for all n realizations up front (~9.6 MB each, ~1 GB at n = 100). Streaming (turning_bands_to_parquet) needs them all per chunk. Storing band values as f32 would halve it but break bit-exactness; left out.
