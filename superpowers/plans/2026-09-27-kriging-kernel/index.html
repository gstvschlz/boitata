    Kriging Kernel Implementation Plan¶

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Make every point-kriging solve (OK, SK, IK, and so SGS, SIS and turning-bands conditioning) about 1.5× faster by replacing the heap-allocated nalgebra LU with a stack-allocated Cholesky kernel. Also provide the primitive that lets multivariate factors share one neighbour search.

    Architecture: krige() keeps its signature and its Estimate output. Internally it first tries kernel::krige, which: - works on up to MAX = 64 samples in fixed stack arrays; - projects the samples once into the variogram frame, relative to the target; - fills only the lower triangle of the covariance matrix; - factors it with Cholesky; - handles ordinary kriging's constraint by the Schur complement (two triangular solves plus μ).

    Systems the kernel cannot hold go to today's LU path, unchanged: - more than 64 samples; - a variogram without a sill (power model).

    A covariance matrix that is not positive definite is an error (EstimError::Singular), not a fallback (decided 2026-09-27: never trade accuracy for speed silently). This is a behaviour change: systems LU solves today, such as a Circular model used in 3D or a near-singular Gaussian system, now fail with a message naming the cause.

    Separately, search.rs gains same_neighborhood / neighborhood_groups. They tell plans 3 (turning bands at scale) and 4 (SGS at scale) which factors may share one neighbour search.

    Tech Stack: - Rust (estimation, variogram crates), nalgebra only for Matrix3, criterion benches. - No new dependencies.

    Global Constraints¶

    • Compute in f64. No panics on user input; errors go through EstimError (thiserror), no anyhow.
    • Deterministic: identical output for any thread count. The kernel is a pure per-target function, and existing 1-vs-8-thread tests must keep passing.
    • Don't add a dependency for what a few lines do. No unsafe without a benchmark.
    • Never name external geostatistics libraries anywhere: code, comments, commits, PRs.
    • Conventional commits, with no co-author or AI-attribution trailers. Use a branch plus a PR to main; never commit to main.
    • PRs ≤ ~400 changed lines. PR and issue bodies are a few lines with no sections.
    • Rust/Python parity: krige()'s public API doesn't change, so bindings and .pyi stubs are untouched. Say so in the PR body.
    • Never commit AGENTS.md, CLAUDE.md or this plan file.
    • Run everything through mise: mise exec -- cargo ... and mise run verify.
    • No silent jitter and no silent fallback. A non-positive-definite system is never regularized nor handed to LU: the kernel returns EstimError::Singular.

    Replace the stub krige in kernel.rs with:

    use crate::error::EstimError;
use nalgebra::Vector3;

/// Packed lower triangle of an `MAX × MAX` matrix, row after row.
const TRI: usize = MAX * (MAX + 1) / 2;

/// Pivots at or below this fraction of the sill make the system singular.
const PIVOT: f64 = 1e-12;

/// Kriging on the stack, or `None` when the system is beyond it (no or more
/// than [`MAX`] samples, a variogram without a sill), which
/// [`crate::krige::krige_lu`] then takes. A covariance matrix that is not
/// positive definite (duplicates without nugget, a model not valid in 3D) is
/// [`EstimError::Singular`].
pub(crate) fn krige(
    kind: Kind,
    target: &(f64, f64, f64),
    samples: &[Sample],
    vg: &Variogram,
) -> Option<Result<Estimate>> {
    let n = samples.len();
    if n == 0 || n > MAX || !vg.is_stationary() {
        return None;
    }
    // Samples relative to the target, in the variogram's frame, so every
    // lag is a Euclidean norm and large coordinates lose no precision.
    let frame = vg.anisotropy.as_ref().map(|a| a.matrix());
    let mut p = [[0.0f64; 3]; MAX];
    for (q, s) in p.iter_mut().zip(samples) {
        let d = Vector3::new(s.loc.0 - target.0, s.loc.1 - target.1, s.loc.2 - target.2);
        let d = frame.map_or(d, |m| m * d);
        *q = [d.x, d.y, d.z];
    }
    let norm = |a: &[f64; 3], b: &[f64; 3]| {
        ((a[0] - b[0]).powi(2) + (a[1] - b[1]).powi(2) + (a[2] - b[2]).powi(2)).sqrt()
    };
    let c0 = vg.total_sill();
    let mut l = [0.0f64; TRI];
    let mut c = [0.0f64; MAX];
    for i in 0..n {
        let row = i * (i + 1) / 2;
        for j in 0..i {
            l[row + j] = vg.cov(norm(&p[i], &p[j]));
        }
        l[row + i] = c0 + samples[i].error_variance;
        c[i] = vg.cov(norm(&p[i], &[0.0; 3]));
    }
    let dot = |a: &[f64], b: &[f64]| a.iter().zip(b).map(|(x, y)| x * y).sum::<f64>();
    for j in 0..n {
        let rj = j * (j + 1) / 2;
        let d = l[rj + j] - dot(&l[rj..rj + j], &l[rj..rj + j]);
        if !(d > PIVOT * c0) {
            return Some(Err(EstimError::Singular(format!(
                "kriging matrix is not positive definite at sample {j} of {n} (duplicate locations without a nugget, or a model not valid in 3D)"
            ))));
        }
        let d = d.sqrt();
        l[rj + j] = d;
        for i in j + 1..n {
            let ri = i * (i + 1) / 2;
            l[ri + j] = (l[ri + j] - dot(&l[ri..ri + j], &l[rj..rj + j])) / d;
        }
    }
    let solve = |v: &mut [f64; MAX]| {
        for i in 0..n {
            let ri = i * (i + 1) / 2;
            v[i] = (v[i] - dot(&l[ri..ri + i], &v[..i])) / l[ri + i];
        }
        for i in (0..n).rev() {
            let mut s = v[i];
            for k in i + 1..n {
                s -= l[k * (k + 1) / 2 + i] * v[k];
            }
            v[i] = s / l[i * (i + 1) / 2 + i];
        }
    };
    let mut a = c;
    solve(&mut a);
    let ordinary = !matches!(kind, Kind::Simple { .. });
    let mut b = [0.0f64; MAX];
    let mu = if ordinary {
        b[..n].fill(1.0);
        solve(&mut b);
        (a[..n].iter().sum::<f64>() - 1.0) / b[..n].iter().sum::<f64>()
    } else {
        0.0
    };
    let weights: Vec<f64> = (0..n).map(|i| a[i] - mu * b[i]).collect();
    let z = |s: &Sample| match kind {
        Kind::Indicator { threshold } => f64::from(u8::from(s.value <= threshold)),
        _ => s.value,
    };
    let value = match kind {
        Kind::Simple { mean } => {
            mean + weights.iter().zip(samples).map(|(w, s)| w * (s.value - mean)).sum::<f64>()
        }
        Kind::Indicator { .. } => weights
            .iter()
            .zip(samples)
            .map(|(w, s)| w * z(s))
            .sum::<f64>()
            .clamp(0.0, 1.0),
        Kind::Ordinary => weights.iter().zip(samples).map(|(w, s)| w * s.value).sum(),
    };
    let sum_wc: f64 = weights.iter().zip(&c).map(|(w, c)| w * c).sum();
    Some(Ok(Estimate {
        value,
        variance: (c0 - sum_wc - mu).max(0.0),
        n_used: n,
        weights,
        lagrange: mu,
        support_variance: c0,
    }))
}

    Remove the now-unused use crate::error::Result; duplication if clippy complains. EstimError is used by the pivot check.

    Why this matches LU: - The bordered system [C 1; 1ᵀ 0][w; m] = [c; 1] gives w = C⁻¹c − m C⁻¹1 and 1ᵀw = 1. So m = (1ᵀC⁻¹c − 1) / (1ᵀC⁻¹1), which is mu above and equals LU's x[n] (the lagrange field). - The variance formula is unchanged: c0 − Σ w c − μ.

    const LANES: usize = 4;
const NB: usize = 32;
const TB: usize = NB * (NB + 1) / 2;

/// Ordinary kriging of four systems at once, each operation advancing all
/// four lanes; shorter systems are padded with identity rows (weight 0).
/// A lane that is not positive definite comes out NaN.
fn ok_batch4(
    targets: [&(f64, f64, f64); LANES],
    sets: [&[Sample]; LANES],
    vg: &variogram::Variogram,
) -> [f64; LANES] {
    let n = sets.iter().map(|s| s.len()).max().unwrap_or(0);
    assert!(n <= NB);
    let c0 = vg.total_sill();
    let mut l = [[0.0f64; LANES]; TB];
    let mut a = [[0.0f64; LANES]; NB];
    let mut b = [[0.0f64; LANES]; NB];
    for (q, (s, t)) in sets.iter().zip(targets).enumerate() {
        for i in 0..n {
            let row = i * (i + 1) / 2;
            if i < s.len() {
                for j in 0..i {
                    l[row + j][q] = vg.cov_points(&s[i].loc, &s[j].loc);
                }
                l[row + i][q] = c0;
                a[i][q] = vg.cov_points(&s[i].loc, t);
                b[i][q] = 1.0;
            } else {
                l[row + i][q] = 1.0;
            }
        }
    }
    for j in 0..n {
        let rj = j * (j + 1) / 2;
        let mut d = l[rj + j];
        for k in 0..j {
            for q in 0..LANES {
                d[q] -= l[rj + k][q] * l[rj + k][q];
            }
        }
        let d = d.map(f64::sqrt);
        l[rj + j] = d;
        for i in j + 1..n {
            let ri = i * (i + 1) / 2;
            let mut v = l[ri + j];
            for k in 0..j {
                for q in 0..LANES {
                    v[q] -= l[ri + k][q] * l[rj + k][q];
                }
            }
            for q in 0..LANES {
                v[q] /= d[q];
            }
            l[ri + j] = v;
        }
    }
    let solve = |v: &mut [[f64; LANES]; NB]| {
        for i in 0..n {
            let ri = i * (i + 1) / 2;
            for k in 0..i {
                for q in 0..LANES {
                    v[i][q] -= l[ri + k][q] * v[k][q];
                }
            }
            for q in 0..LANES {
                v[i][q] /= l[ri + i][q];
            }
        }
        for i in (0..n).rev() {
            for k in i + 1..n {
                let lk = l[k * (k + 1) / 2 + i];
                for q in 0..LANES {
                    v[i][q] -= lk[q] * v[k][q];
                }
            }
            for q in 0..LANES {
                v[i][q] /= l[i * (i + 1) / 2 + i][q];
            }
        }
    };
    solve(&mut a);
    solve(&mut b);
    std::array::from_fn(|q| {
        let s = sets[q];
        let sa: f64 = (0..s.len()).map(|i| a[i][q]).sum();
        let sb: f64 = (0..s.len()).map(|i| b[i][q]).sum();
        let mu = (sa - 1.0) / sb;
        (0..s.len()).map(|i| (a[i][q] - mu * b[i][q]) * s[i].value).sum()
    })
}

    /// Whether `a` with variogram `va` and `b` with `vb` select the same
/// neighbors from the same sample locations, whatever the values: same
/// parameters and ellipsoid, and no high-grade restriction, which depends
/// on values.
pub fn same_neighborhood(
    a: &Search,
    va: Option<&Variogram>,
    b: &Search,
    vb: Option<&Variogram>,
) -> bool {
    a.high_grade.is_none()
        && b.high_grade.is_none()
        && a.min_samples == b.min_samples
        && a.max_samples == b.max_samples
        && a.radius == b.radius
        && a.max_per_hole == b.max_per_hole
        && a.octant == b.octant
        && a.soft == b.soft
        && metric(a, va).map(|m| &m.angles) == metric(b, vb).map(|m| &m.angles)
}

/// Indices of `searches` grouped by [`same_neighborhood`]: each group in
/// index order, groups in the order of their first index.
pub fn neighborhood_groups(searches: &[(&Search, Option<&Variogram>)]) -> Vec<Vec<usize>> {
    let mut groups: Vec<Vec<usize>> = vec![];
    for (i, &(s, v)) in searches.iter().enumerate() {
        match groups.iter_mut().find(|g| {
            let (t, w) = searches[g[0]];
            same_neighborhood(s, v, t, w)
        }) {
            Some(g) => g.push(i),
            None => groups.push(vec![i]),
        }
    }
    groups
}

    Open questions¶

    1. Resolved 2026-09-27: a non-positive-definite matrix raises Singular; no LU fallback.
    2. Tolerance vs LU. 1e-9 relative, not 1e-10 absolute. Weights near ill-conditioning and UTM-sized data can differ by more than 1e-10 between two valid factorizations. The kernel's target-relative frame is arguably more accurate than LU's absolute lags.
    3. MAX = 64. The packed triangle is about 16.6 KB of stack per call, fine on rayon's default 2 MB worker stacks. Raise it if users run max_samples above 64 often; LU still handles them.
    4. Where Task 4 lands. It has no caller until plans 3 and 4. Merge it now as a primitive, or fold it into plan 3's first PR.
    5. Block kriging (block.rs) and cokriging (cokrige.rs) keep their own LU paths. They could reuse the kernel later if benchmarks show they matter at scale.
