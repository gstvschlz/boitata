    Simulation Output and Parquet Writer Implementation Plan¶

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

    Goal: Simulations always return summary maps and keep only the realizations the user selects (keep=False | True | [indices]), and Parquet files are written several times faster with the same bytes on any thread count.

    Architecture: A Keep enum in simulation::post replaces ContinuousOptions::keep: bool and the keep: bool of categorical; summaries carry kept indices beside the kept rows. In ceres-io, a private Encoder replaces ArrowWriter: it slices each batch into row groups, encodes every (row group, column) pair in parallel with rayon, and appends the chunks in order; writer properties pick BYTE_STREAM_SPLIT for floats, DELTA_BINARY_PACKED for the cell index and no dictionary for floats. turning_bands_to_parquet streams kept realizations as columns and hands encoding to a second thread through a depth-1 channel. Python write_parquet releases the GIL, keeps float32 as float32 and writes Arrow batches without concatenating them.

    Tech Stack: Rust (parquet 59.3 ArrowRowGroupWriterFactory, arrow 59, rayon), pyo3, numpy, pytest, criterion.

impl Keep {
    pub fn keeps(&self, k: usize) -> bool {
        match self {
            Keep::None => false,
            Keep::All => true,
            Keep::Indices(indices) => indices.contains(&k),
        }
    }

    /// The kept realizations of `0..n`, ascending.
    pub fn kept(&self, n: usize) -> Vec<usize> {
        (0..n).filter(|&k| self.keeps(k)).collect()

    /// Every index is below `n` and listed once.
    pub fn validate(&self, n: usize) -> Result<()> {
        let Keep::Indices(indices) = self else {
            return Ok(());

            if k >= n {
                return Err(SimError::InvalidParameters(format!(
                    "keep lists realization {k}, but there are {n}; indices start at 0"
                )));
            }
            if indices[..position].contains(&k) {
                return Err(SimError::InvalidParameters(format!(
                    "keep lists realization {k} twice"
                )));
            }
        }
        Ok(())
    }
}

    use arrow_schema::SchemaRef;
use parquet::arrow::arrow_writer::{
    ArrowColumnChunk, ArrowColumnWriter, ArrowLeafColumn, ArrowRowGroupWriterFactory,
    compute_leaves,
};
use parquet::file::writer::SerializedFileWriter;
use rayon::prelude::*;

    /// A Parquet file whose row groups are encoded column by column in
/// parallel and appended in order, so its bytes do not depend on the
/// number of threads.
struct Encoder {
    file: SerializedFileWriter<File>,
    factory: ArrowRowGroupWriterFactory,
    schema: SchemaRef,
    group: usize,
}

impl Encoder {
    /// A file of row groups of at most `group` rows.
    fn create(file: File, schema: SchemaRef, group: usize) -> Result<Self> {
        let props = properties(&schema);
        let (file, factory) =
            ArrowWriter::try_new(file, schema.clone(), Some(props))?.into_serialized_writer()?;
        Ok(Self {
            file,
            factory,
            schema,
            group,
        })
    }

    /// Appends `batch` as row groups, encoding up to one row group per
    /// thread at a time.
    fn write(&mut self, batch: &RecordBatch) -> Result<()> {
        let rows = batch.num_rows();
        let starts: Vec<usize> = (0..rows).step_by(self.group.max(1)).collect();
        for wave in starts.chunks(rayon::current_num_threads().max(1)) {
            let first = self.file.flushed_row_groups().len();
            let mut jobs: Vec<Vec<(ArrowColumnWriter, ArrowLeafColumn)>> = vec![];
            for (g, &start) in wave.iter().enumerate() {
                let slice = batch.slice(start, self.group.min(rows - start));
                let mut writers = self.factory.create_column_writers(first + g)?.into_iter();
                let mut job = vec![];
                for (field, column) in self.schema.fields().iter().zip(slice.columns()) {
                    for leaf in compute_leaves(field, column)? {
                        job.push((writers.next().expect("one writer per leaf"), leaf));
                    }
                }
                jobs.push(job);
            }
            let groups: Vec<Vec<ArrowColumnChunk>> = jobs
                .into_par_iter()
                .map(|job| {
                    job.into_par_iter()
                        .map(|(mut writer, leaf)| {
                            writer.write(&leaf)?;
                            writer.close()
                        })
                        .collect::<parquet::errors::Result<Vec<_>>>()
                })
                .collect::<parquet::errors::Result<_>>()?;
            for chunks in groups {
                let mut group = self.file.next_row_group()?;
                for chunk in chunks {
                    chunk.append_to_row_group(&mut group)?;
                }
                group.close()?;
            }
        }
        Ok(())
    }

    fn finish(self) -> Result<()> {
        self.file.close()?;
        Ok(())
    }
}

    The wave size depends on the thread count, but it only bounds memory: every row group is encoded on its own and appended in file order, so the bytes don't change. ArrowWriter::try_new(...).into_serialized_writer() keeps the embedded Arrow schema and the ceres metadata exactly as before.
